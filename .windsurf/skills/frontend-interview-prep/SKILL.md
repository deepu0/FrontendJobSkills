# Frontend Interview Prep

Calibrate to the job they named. Generic leetcode dumps waste a week.

## When to Use

- Upcoming frontend interview
- They pasted a JD and asked what to study

## Tracks (pick from the JD)

**JS (always):** closures, `this`, event loop, promises, debounce/throttle from scratch, memoize, `==` traps, `Array.sort` default.

**React (default):** reconciliation/keys, useEffect deps, memo/callback when not to, context vs Zustand/Redux, RSC/client boundary, custom hooks extract logic not JSX.

**System design (mid+):** news feed, component library, autocomplete, image gallery, realtime dashboard. Always: perf budget, a11y, empty/loading/error, offline.

**Live coding:** debounced search, `useDebounce` / `useLocalStorage`, flatten nest, tabs with keyboard, pub/sub, CSS center + auto-fit grid.

**Take-home:** README is half the grade. Loading/error/empty. TypeScript + a few tests. Match their stack. No Redux for a counter.

**STAR stories they must have:** a perf fix with numbers, a designer/PM disagreement, a migration, an a11y push, a time they deleted complexity.
